# 점심 추천 로직

## Decisions

- 날씨·계절 조건과 음식 카테고리를 잇는 로직은 규칙 기반 매핑으로 처리한다.
  AI 모델을 이용한 추천 생성은 쓰지 않는다.

## Boundaries

- 이 결정은 "오늘 날씨 기반 점심 맛집 추천" 작업 단위와, 이후 같은 추천
  로직을 재사용하는 기능에 적용된다. 그룹 투표처럼 사람이 직접 후보를 고르는
  단계에는 적용되지 않는다.

## Why

규칙 기반은 외부 AI 연동(API 키, 비용, 응답 지연·실패 처리)이 필요 없어 한
번에 구현하고 실제 동작으로 검증하기 쉽고, 같은 조건에서 같은 카테고리가
나오므로 결과를 예측하고 검증하기도 쉽다.

## Reconsider when

- 미리 정의한 규칙만으로는 다루기 어려운 조건(예: 미세먼지, 개인 상황)까지
  반영해야 한다는 요구가 확정되는 경우.
- 규칙 테이블이 지나치게 커져 유지관리 비용이 매핑 방식을 바꾸는 비용보다
  커지는 경우.

## Still-rejected alternatives

- AI 모델 기반 추천 — 더 유연하고 자연스러운 문구 생성이 가능하지만 별도
  API 연동·비용·응답 지연 처리가 범위에 추가돼 이번 범위에서는 제외; 위
  재검토 조건이 충족되면 재검토.
